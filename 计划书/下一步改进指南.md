### 2.2 Plan-Execute 分离（v11 P1，2-3d）

**痛点**：当前 `ReactLoopAgent`（`loop.py:run_turn`）是 ReAct 循环（每步 LLM 决策 → 工具 → 再 LLM），**长链路任务（10+ 步）每步都调 LLM 决策，慢且贵**；复杂任务无全局 Plan。

**目标**：升级为 Plan-Execute 范式（参考 LangGraph `plan-and-execute` / BabyAGI / OpenAI `o1` 式 plan-then-act）：先 Plan 阶段 LLM 生成完整步骤序列，Execute 阶段并行/串行执行，必要时 Re-Plan。

**落地方案**（不重构 `loop.py`，新增 `plan_execute_loop.py`）：
1. `src/core/agent/plan_execute_loop.py`（新建，<300 行）：
   - `PlanExecuteAgent`：`plan(task) -> List[Step]` → `execute(steps, parallel_safe=True) -> Results` → `re_plan_if_needed`
   - Plan 阶段调 LLM 一次生成 JSON 步骤序列（复用 `src/core/agent_prompt.py` 的 plan 提示词模板）
   - Execute 阶段用 `ParallelExecutor`（读锁共享/写锁独占，已有）并行无依赖步骤
   - Re-Plan：执行结果偏差 >阈值 时回 LLM 重规划（最多 2 次）
2. `Turn`（`turn.py`）扩展 `plan_execute` phase（不改现有 15 phase，**新增** `PLAN_EXECUTE_START` / `PLAN_EXECUTE_END` 两个 phase，向后兼容）
3. `src/web/routers/agent.py` 加 `POST /api/agent/plan_execute`：调 `PlanExecuteAgent`，SSE 推 plan/execute/replan 事件
4. 前端 `webapp/src/app/(app)/agent/page.tsx`：新增"Plan-Execute 模式"开关，展示步骤甘特图

**验证**：`tests/test_plan_execute.py`（新建）：Mock LLM 返回 3 步 plan → 并行执行 → 结果聚合 → Re-Plan 触发条件。覆盖率 ≥85%。
