# 电商卖家运营（ecommerce-merchant）

## 适用场景

用户要求"上架商品""改价""调整库存"等卖家运营操作时激活。

## 安全边界（必读）

- 读操作（查询商品/库存/价格）可自由执行。
- 写操作（上架/改价/库存变更）为高危操作：
  - 必须经 scope_guard 审批（Ask 信号 → 人工确认）。
  - 仅当对应 VAP_ALLOW_WRITE_* 开关置 1 且人工批准后才执行。
  - 当前所有电商写操作仅本地 Mock，绝不真实调用任何电商平台。
- 无审批放行时，流程止步于「提交审批」，不执行写操作。

## 工作流（计划→审批→执行）

1. 采集需求：商品名称、类目、目标价、成本、初始库存。
2. 生成计划：按下方决策表输出建议定价与补货阈值。
3. 提交审批：把计划写入审批请求（含变更前/后对比）。
4. 等待批准：未获批准不执行任何写操作。
5. 执行：批准后按计划执行上架/改价/库存更新（Mock）。

## 决策表：定价策略

| 场景 | 规则 | 公式 |
|------|------|------|
| 常规上架 | 成本加成法 | 售价 = 成本 × (1 + 目标毛利率) |
| 竞争对标 | 跟随市场 | 参考同款均价 ±5% |
| 清仓促销 | 折扣上限 | 售价 ≥ 成本 × 0.8 |
| 引流款 | 保本定价 | 售价 = 成本（靠关联销售盈利） |

## 决策表：库存阈值

| 场景 | 规则 |
|------|------|
| 安全库存 | 覆盖 7 天日均销量 |
| 补货触发 | 库存 ≤ 安全库存 × 1.2 |
| 上限预警 | 库存 > 60 天销量 → 停止补货并评估降价 |
| 缺货处理 | 库存 = 0 → 标记下架或预售 |

## 输出格式

```markdown
## 运营计划
- 商品：<名称>
- 建议售价：<价格>（依据：<策略>）
- 建议库存：<数量>（阈值：<规则>）
- 审批状态：<待审批 / 已批准 / 已拒绝>
- 执行记录：<Mock 日志>
```
